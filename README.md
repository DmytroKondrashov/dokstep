# Dokstep

Конструктор документообігу за зразками. Користувач створює **процес** (workflow) з
послідовних **кроків**, завантажує до кожного кроку один або кілька заповнених зразків
`.docx` і **виділяє в них змінні частини**. Потім за процесом формуються нові документи:
вводяться лише поля, решта береться з попередніх кроків.

Узагальнена версія `systema_avtomatyzatsii_dilovodstva`. Там шаблони й логіка написані в
коді під кожен процес, а тут усе налаштовується в інтерфейсі.

## Як це працює

1. **Процес → кроки → зразки.** На кроці завантажуються `.docx`; сервер будує попередній
   перегляд (абзаци, таблиці, колонтитули, базове форматування).
2. **Позначки.** Виділіть фрагмент у перегляді (виділення доповнюється до цілих слів;
   Alt/Shift вимикає це):
   - **Нове поле** (жовте) вводиться при формуванні. Якщо фрагмент стоїть у похідній
     формі (родовий відмінок тощо), задайте значення в базовій формі та форму фрагмента.
   - **Взяти з поля…** (зелене) бере поле цього або попереднього кроку з перетворенням.
3. **Перетворення:** відмінок (ПІБ, звання або посада через shevchenko.js + military ext),
   формат імені (`ПРІЗВИЩЕ Ім’я По батькові`, `Ім’я ПРІЗВИЩЕ`, `І.П. ПРІЗВИЩЕ`, …), регістр, дата (± днів,
   `05.08.2026` / `5 серпня 2026 року` / `«05» серпня 2026 року`).
4. **Підказки.** Для кожного кроку сервер шукає в документах значення полів (свого й
   попередніх кроків) у всіх відмінках і форматах і пропонує позначити їх одним кліком.
5. **Автозаповнення поля:** поле може за замовчуванням брати значення з іншого поля
   (напр. «дата характеристики = дата наказу + 10 днів»). Порожнє = авто, ✎ = редагувати.
6. **Справа (run)** — набір введених значень. Документи завантажуються по одному, по
   кроку або все разом (`.zip`, тека на крок). Назву файлу можна задати шаблоном
   `Наказ {ПІБ}`.

### Заповнення `.docx`

Позначка — це `(частина#номер абзацу, start, end)` у тексті абзацу (`<w:t>` +
`<w:tab>`=`\t` + `<w:br>`=`\n`). Під час формування сервер розрізає run-и на межах
діапазону й ставить значення в перший run. Форматування зберігається, виділення
(жовте/зелене) знімається. Шаблони з `[[TOKEN]]` не потрібні, оригінал не змінюється.
Код: `src/lib/server/docx/` (`xml.ts` — модель абзаців, `preview.ts`, `fill.ts`).

## Запуск

Потрібен Node ≥ 22.13 (вбудований `node:sqlite`).

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # vitest
npm run check        # svelte-check
npm run build && node build   # прод; дані в ./data (DATA_DIR=...)
```

**Приклад.** На головній сторінці кнопка «Відкрити приклад» створює процес «Прийняття на
роботу»: заява → наказ → трудовий договір, з уже позначеними полями. Зразки документів
генеруються в коді (`src/lib/server/demo.ts`), а `tests/demo.test.ts` перевіряє формування
з новими даними.

Дані: `data/dokstep.db` (SQLite). Визначення процесів зберігаються як JSON, зразки — як
BLOB. Великі зразки: `BODY_SIZE_LIMIT=20M node build`.

## Структура

```
src/lib/types.ts            модель: Workflow / Step / Field / Mark / Transform / Run
src/lib/transform.ts        перетворення (дати, імена, регістр) — спільне для клієнта і сервера
src/lib/editor.ts           чисті функції редактора (входження, каскадне видалення)
src/lib/server/db.ts        SQLite
src/lib/server/engine.ts    значення полів, формування, підказки
src/lib/server/transform.ts відмінювання (shevchenko)
src/lib/components/         DocPreview (виділення → офсети), MarkPopover, TransformEditor
src/routes/workflows/[id]   редактор процесу
src/routes/runs/[runId]     майстер формування документів
```

## Що далі

- Повторювані блоки (рядки таблиці, абзаци на кожного свідка), як `EACH`/`EACHB` у старому проєкті.
- Необов’язкові абзаци (прибрати, якщо поле порожнє).
- Експорт/імпорт процесу (JSON + зразки), щоб ділитися налаштованими процесами.
- Типи полів (дата з календарем, вибір зі списку), обчислювані поля.
- Користувачі/доступ, якщо це стане сервісом.
